# next-route-kit 0.1.0

[简体中文](../zh-CN/release/v0.1.0.md) · **English**

Status: first public release baseline.

## Packages

| Package                   | Purpose                                            | Install                               |
| ------------------------- | -------------------------------------------------- | ------------------------------------- |
| `next-route-kit`          | Next.js App Router Route Factory and input sources | `pnpm add next-route-kit`             |
| `@next-route-kit/core`    | Framework-neutral contracts and pipeline runtime   | `pnpm add @next-route-kit/core`       |
| `@next-route-kit/zod`     | Optional Zod 4 validation adapter                  | `pnpm add @next-route-kit/zod zod`    |
| `@next-route-kit/testing` | Runner-neutral Request/Response test helpers       | `pnpm add -D @next-route-kit/testing` |

## Included contract

The release preserves the native `app/**/route.ts` convention and provides the
following request lifecycle:

```text
Next params hydration
  → Middleware
  → Guard
  → Interceptor (enter)
  → declared body/query resolution
  → Pipe
  → Handler
  → Interceptor (exit)
  → Middleware (exit)
  → Response Serializer
```

Factories are class-backed and immutable, with explicit Global → Scope → Route
composition. Inherited security components cannot be removed by a child route
in this release.

## Compatibility

The release is verified against Next.js 15.5.23 and 16.3.1, including Node
Route Handlers in both versions, an Edge Route Handler in Next 15, async dynamic
params, production builds, and Turbopack development servers. See the
[compatibility matrix](../compatibility/next-matrix.md).

## Validation and errors

- Core is validator-agnostic.
- `@next-route-kit/zod` targets Zod 4 and uses asynchronous parsing.
- Zod is never installed or registered by the main package; API envelope users
  map `ZodValidationError` through `apiResponsePlugin({ mapError })`.
- The main package maps `HttpError` and malformed JSON by default.
- Custom ExceptionFilters run before the built-in filter.
- Unexpected errors continue to Next.js's error boundary.

## Deliberate boundaries

This is a 0.x first public release. It does not provide controllers,
decorators, dependency injection, file-system route scanning, automatic
`next.config.ts` registration, or a replacement router. Next.js `proxy.ts` is a
separate boundary.

The public package versions are set directly to `0.1.0` for this initial
baseline. Subsequent public API changes must use a non-empty Changeset and the
version workflow described in the [release checklist](./release-checklist.md).

## Verification record

The release gate has passed locally with all package tests, strict type checking, ESLint,
Prettier, package builds, packed external-consumer checks, and Next.js 15/16
production and Turbopack development smoke tests. The Next 15 fixture's real
Edge App Route keeps Next.js's documented static-generation warning; the Next
16 Edge deprecation warning and the Next 15 ESLint plugin-detection warning are
no longer emitted.
